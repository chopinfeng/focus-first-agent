# FFA 界面规范：以保护注意力为唯一目标

> 版本 0.1，2026-09-03。适用于 FFA 的全部呈现面：周边状态、异常收件箱、"已替你决定"队列、digest、自治面板、手机推送、终端状态行。原则来自平静技术、航空告警设计、Amershi 18 条与本项目两轮调研；可点原型见 `docs/ui-prototype.html`，在线版 https://claude.ai/code/artifact/e388218d-e893-48f4-bf95-9824704f05f2 。

## 0. 一句话

**界面的成功状态是"什么都没有"。** 一个正常运转的 FFA 界面在大多数时间应当是空的、暗的、静止的。任何像素、任何文字、任何动效都要证明它值得人的一次注视。

## 1. 十条原则

| # | 原则 | 含义 | 反例 |
|---|---|---|---|
| 1 | **暗舱（dark cockpit）** | 正常即无灯。working 不显示，只有 blocked / needs-you / done 出现 | 每个 Agent 一个旋转 spinner、流式输出滚动 |
| 2 | **一眼即懂（glanceability）** | 周边信息用颜色和位置编码，≤ 1 秒读完，不用文字 | 状态栏里写 "Agent 3 is running tests (41/41)…" |
| 3 | **一次一屏，不滚动** | 一条决策的全部信息在一屏内；收件箱首屏 ≤ 5 条 | 无限列表、折叠再折叠 |
| 4 | **决策优先于信息** | 首屏只放"要你做什么"和选项，证据在展开层 | 先放 diff 再放问题 |
| 5 | **单键作答** | 每条请求可用 1/2/3 或 y/n 回答；鼠标是次选 | 必须点开、滚动、再点确认 |
| 6 | **静止** | 内容不自动移动、不自动刷新位置；新条目进入不推挤正在读的条目 | 列表顶部实时插入、toast 堆叠 |
| 7 | **不计数** | 没有未读数、红点、"inbox zero" 进度条 | 角标 "12"、"你还有 7 条待处理" |
| 8 | **默认无声** | 没有声音、没有振动；Warning 也只用一次可确认的提示 | 每次完成叮一声 |
| 9 | **说明代价** | 每条请求显示阅读预估、不答会怎样、剩余时间 | 只有 "Approve / Deny" |
| 10 | **可关的一切都可关** | 抑制、snooze、降级都是一键；被抑制的东西可见但不打扰 | 关掉通知就完全失联 |

## 2. 界面的注意力预算

界面本身也有预算，和内核的预算一样可度量：

| 预算 | 上限 | 度量 |
|---|---|---|
| 周边状态每次注视 | ≤ 1 秒读完 | 眼动或自评 |
| 收件箱一条的首屏阅读 | ≤ 20 秒，≤ 60 个汉字 + 3 个选项 | 字数统计 + 停留时间 |
| 收件箱首屏条数 | ≤ 5 条，其余折叠为"另有 N 条 Advisory" | 布局约束 |
| 从打开到第一次决策 | 中位 ≤ 90 秒 | time_to_first_decision |
| 决策所需滚动 | 0 | scroll depth |
| digest 一屏 | ≤ 25 行 | 渲染约束 |
| 动效 | 仅状态变化时一次，≤ 200 ms，尊重 reduced-motion | 代码审查 |
| 颜色 | 一个强调色（needs-you），语义色只有黄 / 橙 / 绿 / 红四个 | 设计 token |

## 3. 逐个呈现面

### 3.1 周边状态（菜单栏 / 终端状态行 / IDE 状态栏）
- 形态：每个 Agent 一个 8 px 圆点，无文字。全部正常时整个区域为空或只有一个极淡的占位。
- 编码：黄 = blocked（等环境或等验证），橙 = needs-you（有 Caution 及以上等你），绿 = done（有证据包待看），灰点 = 已抑制/已 snooze（独立可见，不许显示为正常）。
- 橙点允许一次 2 秒的呼吸动画，之后静止。红只用于 Warning，且伴随一次可确认提示。
- 悬停才显示 Agent 名和一行 headline；点击直达收件箱对应条目（deep link）。
- 专注模式下状态区显示"已抑制 N"的灰色数字，这是唯一允许的计数。

### 3.2 异常收件箱
- **排序**：Warning → Caution（按 point of no return / TTL）→ Advisory（按历史行动概率）。不按时间。
- **首屏结构**（一条）：
  1. 级别标签 + 类型 + 决策类别（一行小字）
  2. headline（≤ 120 字符，写对人的影响）
  3. 四行 context：you_were / i_did / i_need / blast_radius
  4. why_now 一行
  5. 选项（推荐项高亮，带单键提示与后果）
  6. 底行：不答会怎样 · 剩余 TTL · 预计阅读时间 · 展开证据
- **展开层**（点击或按 e）：proof 列表、what_would_prove_me_wrong、diff、transcript 链接。展开不跳转，就地展开，其他条目不动。
- **交互**：j/k 移动，1/2/3 选项，e 展开，s snooze（30 min / 到下一个断点 / 到明天），d 降级为 Advisory，f "不该问我"，l "该早点问"。每个键都在界面上可见。
- **回答后**：条目淡出 200 ms，位置留白 1 秒后收起，不推挤。不弹 "Approved!" toast。
- **空状态**：一句话"没有需要你的事"，加下一次 digest 的时间。这是目标状态，要设计得让人愿意停留 0 秒。
- **禁止**：未读数、"全部批准"按钮、"全部已读"按钮、自动刷新插入、把 transcript 当正文。

### 3.3 "已替你决定"队列
- 独立视图，不混进收件箱。每条：做了什么决定、为何没问（why_not_asked）、依据的默认项、一键 undo、剩余可撤销时间。
- 按可撤销剩余时间排序，快过期的在上。
- 不可逆项永远不会出现在这里（内核保证），界面上要写明这一点，建立信任。

### 3.4 Digest
- 触发：粗断点或每 30 分钟，作为一条可展开的条目出现在收件箱底部，不推送。
- 结构：三段固定顺序。① 需要你的（若有，通常为空，因为已在收件箱）② 已替你决定的 N 项 ③ 进度：每个 Agent 一行，"做了什么 / 下一步 / 风险"。
- 按历史行动概率排序，低概率项折叠。≤ 25 行，超出即折叠。
- 每条可逆动作带 undo；没有"全部已读"。

### 3.5 自治面板
- 一屏：全局 autonomy slider（L0–L5）、各动作类当前等级（可编辑 allowlist）、速率仪表（本小时 N/6）、优先级分布（三色条）、已抑制计数、退化信号（四个指示，正常为空）。
- 这是唯一可以出现数字的界面，因为它是设置页而非通知面。默认不打开。

### 3.6 手机推送
- 只有 Warning 与 AWAY 状态下的 Caution-now 会到手机。
- 正文格式固定：`[级别] headline · 推荐：X · 不答：Y · 剩余 Z`。不写 "Agent is waiting for your input"。
- 通知动作：推荐项、第二选项、"回到桌面处理"。回答后所有渠道 3 秒内同步消失。
- 对齐 OS 打断等级：Warning = Time-Sensitive，其余 = Active/Passive。Critical 需人预授权。

### 3.7 终端内（Claude Code 等）
- 状态行只放圆点；不在输出流里插入提示文本。
- 收件箱用 `ffa inbox` 打开为全屏 TUI，退出即回到原上下文；不劫持当前会话的输入。

## 4. 卡片的信息层级（一条 AttentionRequest 的渲染规则）

```
第一眼（≤ 3 秒）   级别色 + headline
第二眼（≤ 20 秒）  四行 context + why_now + 选项与后果 + 底行
主动展开           proof / what_would_prove_me_wrong / diff / transcript
```
文字预算：首屏 ≤ 60 个汉字或 120 个英文单词。超出的内容自动移入展开层，并在底行显示"展开 · 约 40 秒"。

## 5. 视觉 token

- 强调色只有一个：needs-you 的琥珀。品牌色不出现在通知面。
- 语义色：黄（blocked）、橙（needs-you）、绿（done）、红（Warning）。Advisory 无色。
- 字体：正文系统字体；headline 用稍重的字重而非更大的字号；数字用等宽。
- 深浅主题都要设计，深色下降低饱和度，保证橙点在深底上不刺眼。
- 图标最少化：级别用文字标签，不用图标猜谜。

## 6. 反模式清单（评审时逐条对照）

1. 任何形式的未读计数与红点
2. 自动播放、流式滚动、spinner 常驻
3. 新内容插入到用户正在读的位置
4. 需要滚动才能看到选项
5. 模态弹窗抢焦点
6. "全部批准 / 全部已读"
7. 通知正文不含 headline 与默认项
8. 声音或振动默认开启
9. 被抑制的内容完全消失
10. 把 Agent 的 transcript 当作首屏
11. 用品牌色或渐变装饰通知面
12. 空状态用插画或鼓励语填满

## 7. 如何验证界面本身

- E3（信息形态）直接测卡片层级；E9/E10 测周边状态与 digest。
- 界面级指标：time_to_first_decision、每条停留时间、scroll depth（目标 0）、proof 展开率、误触率（按错键后 5 秒内撤销）、空状态停留时间（目标接近 0）。
- 每个新界面元素上线前回答一个问题："去掉它，注意力成本会上升吗？"不能证明就不加。
