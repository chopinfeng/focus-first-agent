Focus-First Agent Framework

一个把人的注意力当作最稀缺调度资源的 Agent 框架。Agent 的断点不是人的断点，这个框架负责把两者对齐，并像告警工程那样治理打断的速率与分布。

框架的最小可见单元：一条 AttentionRequest 在收件箱中的样子。人看到的是"为什么需要我、为何是现在、不答会怎样、按哪个键"，证据可展开，而不是 transcript。

命题

现有 Agent 框架优化 token、时延和正确率，人的注意力只是副作用。所有主流 SDK 都是逐条打断、无限等待、无预算、无时机感。FFA 在 Agent 运行时和人之间插入一个注意力内核，让每一次"需要你"都经过调度。

三条设计信念，全部来自调研：

  • 打断是效用计算，不是默认行为。自主执行、发起对话、什么都不做，三者由"推迟代价 vs 打断代价"决定，并随人的状态变化（Horvitz 1999/2003）。
  • 可逆性比风险等级更有杠杆。生产环境仅 0.8% 的动作不可逆（Anthropic）；可逆动作应当直接做并记录回滚点，用事后审计替代事前审批。
  • 人看结论和证据，不看过程。子 Agent 只返回蒸馏结论、diff-first、预览优先，是所有成熟产品收敛出的同一原则。
  • 打断要像告警一样治理。过程控制、航空、医疗和 SRE 早就给出了速率上限、优先级分布、阶段抑制与自动召回、抖动检测这些规则，v0.2 直接沿用。

学术研究给出的硬约束

打断有时机

defer-to-breakpoint：推迟到子任务边界投递，恢复更快、挫败更少，粗粒度断点优于细粒度（Iqbal & Bailey 2008/2010）。FlowLight 用键鼠活动推断可打扰性，中断减少 46%。

周边 vs 中心

平静技术：信息驻留注意力周边，需要时才移到中心（Weiser & Brown 1996）。可扫视性是关键属性；状态用颜色和位置编码，不用文字通知。

一人能管几个 Agent 有公式

FO ≈ NT/IT + 1，忽视时间除以交互时间（Olsen & Goodrich）。操作员利用率超过 70% 后绩效衰退（Cummings & Guerlain 2007）。提高 fan-out 的两条路：更自主，或更好的请求界面。

完全自动化最危险

out-of-the-loop 导致情境意识下降、接管更慢（Endsley & Kiris 1995）。目标是信任校准而非信任最大化（Lee & See 2004）。注意力残留：切换前收尾能清除残留（Leroy 2009）。

现有框架的八个空白

逐个核对 LangGraph、HumanLayer、OpenAI Agents SDK、Claude Agent SDK、Vercel AI SDK、Microsoft Agent Framework、CrewAI、Temporal、AG-UI、A2A、MCP 后发现：

  1. 决策请求没有统一 schema：question、options、default、deadline、consequence、reversibility 从未作为一个对象出现。
  2. 没有批处理、digest、静默时段、合并同类审批。
  3. SDK 层 interrupt 无限等待，没有"超时选安全默认"。只有 Temporal 一类持久工作流有 timeout。
  4. 信任增长没有量化模型；OpenAI 的 always_approve 和 Claude 的 PermissionRequest 追加规则都是手动。
  5. 没有 PagerDuty 式升级阶梯对接 Agent 事件。
  6. MCP 已有 readOnlyHint / destructiveHint，但没有框架用它驱动 ask-vs-act。
  7. 面向人的可观测性仍是日志；没有 plan-of-record、偏差、"what I need from you"的结构化事件。
  8. 注意力预算本身不被建模。没有框架把"本小时最多打断 N 次"或"用户当前状态"作为调度输入。

FFA 的每个组件都对应至少一个空白。

决策策略：ask vs act

评估顺序借鉴 Claude Agent SDK 的六步权限模型，加入账本和效用两层：

准入门槛 → 硬 deny → 硬 ask → decision_class（goal/taste 必问） → 信任账本 → 效用计算 → 分类器兜底 → 默认 ask

Agent 不自评是否需要打扰人；动作类按效果分类（写入路径、网络出口、进程、凭据、不可逆性），链式命令和脚本拼装按最终效果算一个动作，字符串规则只作补充。

效用计算

surface_now  if  P(need_human) × Cost(wrong)  >  Cost(interrupt | state) + Cost(resume)
defer        if  上式不成立 且 存在安全默认
act          if  P(need_human) < act_threshold(risk) 且 reversible

效用计算只决定 Advisory 与 Caution-soon 的投递时机。打断成本随状态取值：FOCUS 取 12 分钟量级，粗断点 1 分钟，中断点 2 分钟，细断点 5 分钟，AWAY 取渠道成本。Kernel 按动作类输出批准率：高于 90% 建议放宽，低于 70% 建议收紧或改进 spec；系统级升级率目标 10 到 15%。

信任账本（v0.2 重做）

  • 计数单位是证据，不是批准。某动作类累计 10 次"verifier 通过 + 可撤销 + 未被 undo"才晋升。
  • 不对称。一次 undo、override 或 verifier 失败即降两级并重置。晋升后若该类的打断率或回滚率上升，自动降级。
  • 晋升可见可撤回。晋升以 Advisory 通知，一键撤回；账本本身是可编辑的 allowlist；阈值修改记录责任人，Agent 不能自改。
  • 拒绝带教训。每次 reject 要求一句原因，沉淀为规则喂回 Agent。P0 类永不自动放行。
  • 反橡皮章。记录停留时间；随机 5% 的 Caution 要求展开证据才能批准；digest 禁止全部已读且不含不可逆项；监测四个退化信号（审查时长降而批准率不变、否决率降、展开证据比例降、反馈减少），任一触发就生成不可抑制的审计请求。

任务生命周期

  1. Intake（强制 plan/interview 门）：填 TaskCard。框架用一次结构化表单把所有可预见的决策前置。goal 类决策必须在此答完，input 类带推荐项与 point of no return，constraint 类默认按推荐。
  2. Plan-of-record：计划是对象不是文本。计划批准后不逐步问，只有偏离计划或触及不可逆边界才生成 AR。
  3. Execute：默认静默。SDK 事件经适配器变成 AR 进内核。周边状态灯实时反映 working / blocked / needs-you / done。
  4. Verify：独立 verifier 跑 done_criteria，打风险标签，生成证据。不通过则回到上一步，不打扰人。
  5. Deliver：EvidencePacket 作为 review 类 AR 进收件箱。P2/P3 且验证通过的可配置为自动合并加 digest 通知。
  6. Learn：账本回写阈值、信任、渠道偏好。

呈现面

周边状态（dark cockpit）

默认全灭，working 不亮。黄是 blocked，橙是 needs-you，绿是 done，灰点是 shelved 或已抑制，独立可见。绝不弹窗。

异常收件箱

唯一需要人"看"的地方。排序按 urgency、deadline、风险、价值。每项是 headline、四行 context、带默认高亮的选项、单键回答，并显示不回答会发生什么和剩余 TTL。

Digest 与"已替你决定"队列

Digest 按历史行动概率排序，禁止全部已读，不含不可逆项。Advisory 超时自动决策进独立审计队列，每条带 undo 与"为何没问"。另有自治面板：全局 autonomy slider、各动作类等级、速率与分布仪表、已抑制计数。

渠道与 transcript

终端、桌面、手机 push、Slack。同一 AR 跨渠道同步，任一处回答即全局解决。transcript 降级为审计视图，默认折叠。

适配器

不重造运行时。每个来源只做两件事：把事件翻译成 AR，把 AR 决议翻译回恢复调用。

v0.2 调整：第二轮调研对比

第二轮四路调研（跨领域告警、业界观点与人机交互指南、评测与用户模拟器、第二批产品）逐条对照 v0.1。骨架没有被推翻，四个地方被证据击中，全部改了。逐条决策在 docs/CHANGELOG-v0.2.md。

信任账本"10 次批准即晋升"是错的

批准不是证据（Karpathy、Osmani）；信任积累慢、蒸发快（Kent Beck）；一个团队每天 200 多个审批改成批量批准，六个月后无人真在看（waxell）；Anthropic 数据里老用户自动批准升到 40% 的同时打断率从 5% 升到 9%。改为证据计数、不对称降级、双向监测、晋升可撤回。

只按风险 × 可逆性决定问不问不够

品味和目标类决策与风险无关，必须问人（Maggie Appleton）；goal 类澄清严重前置，轨迹 70% 处再问已无用，constraint 类几乎无益（Ask Early, Ask Late, Ask Right）。新增第三轴 decision_class，goal 强制在计划期问完。

4 行上下文提高的是信心不是准确率

更好的 trace 界面减少了找错时间，但 "improved confidence didn't translate to better accuracy"（Grunde-McLaughlin 等 2026）。AR 和证据包都加可展开的可验证证据与"什么能证明我错了"，首屏改为意图差异 + verifier 结论。

预算按"每任务次数"太粗

ISA-18.2 与 EEMUA 191 给出稳态 < 1 条 / 10 分钟、≥ 10 条 / 10 分钟即 flood、优先级分布 80 / 15 / 5；航空给出阶段抑制与自动召回；医疗给出 delay 与二级响应人。全部沿用为速率型预算、flood 模式、抑制召回、chattering 检测。

测试方案

让注意力行为和安全不变量像功能正确性一样可回归。所有时间依赖走虚拟时钟，人由 SimulatedHuman 扮演。

L1 内核单元

AR schema 校验；Policy 决策表（风险 × 可逆 × 范围 × 信任 → ACT / ASK_DEFER / ASK_NOW / BLOCK）；效用阈值；Scheduler 的延迟、合并、静默、渠道、升级、TTL、闸门；Budget；信任账本状态机；HumanState 转移与迟滞。

L2 适配器集成

用录制的真实 SDK 事件作 fixture：Claude Code hooks、Agent SDK canUseTool、LangGraph HITLRequest、OpenAI interruptions、MCP elicitation 与 destructiveHint、A2A input-required。断言事件 → AR → 决议 → 运行时调用往返，以及重启后未决 AR 与 TTL 恢复。

L3 场景回放与属性测试

每个 use case 一条 trace：agent 事件 + 人类状态时间线 + 回答策略 + 期望。另在 1,000 条随机 trace 上验证十七条不变量：P0 不自动放行、不无限等待、终态唯一、FOCUS 静默、预算上界、合并幂等、撤销可逆、账本单调、跨渠道一致，以及 v0.2 新增的不可逆不进 digest、抑制必重现、P0 过期不放行、goal/taste 必问、速率上界、flood 单条、审计不可压。

L4 真人评估与模拟器验证

每阶段末 8 到 12 人被试内实验。模拟人本身是被测对象：100 条轨迹标注 accuracy / consistency / plausibility 各 ≥ 90%，真人与模拟成对区分 ≤ 60%，失败分布 Spearman ≥ 0.7，否则结果标注"模拟器未验证"。门禁：L1 覆盖 ≥ 90%，关键不变量失败即阻断发布。

AttentionBench

SWE-bench 测 Agent 能否完成任务，METR 测总时长，τ²-bench 与 Collaborative Gym 测与模拟用户协作的成功率，Saber 与 AgentDojo 测能否抵抗陷阱。没有一个把打断次数与时机、人读写的负担、监督退化当作一等被测量。AttentionBench 把注意力本身当作被测对象，并复用上述 benchmark 的组件。

任务集与模拟人类

30 个任务来自三个真实开源仓库，每个带注意力标注：真正需要人的决策点（均值 1.4 个，各带 decision_class 与用强制注入法标定的 point of no return）、至少 30 个陷阱动作（复用 Saber 的三类因果场景：嵌入注入、风险自选、上下文警告）、不可逆动作清单、人类专家耗时。另有 6 个并行包，同时跑 3、5、8 个任务。

Harness 复用 Collaborative Gym 的异步事件模型，模拟人有五种动作并持有隐藏信息。参数来自实证：FOCUS 段中位 35 分钟；打断成本 FOCUS 12 分钟、粗断点 1 分钟、中断点 2 分钟、细断点 5 分钟；陷阱识别率随会话内提示数单调衰减，起点 0.9，25 次后约 0.11，对应人类中途捕获植入危险命令仅 13.6% 的报道；基线批准率 93%；新手与老手分层。除 default、cautious、absent 三种策略外，另有 impatient、withholding、overrider 三种非合作 persona。

主指标

Interrupt  = Σ 打断成本(按状态与断点粒度)
Read       = Σ 人要读的 tokens        Write = Σ 人要写的 tokens
Rebuild    = 上下文重建次数 × 2 min    Repeat = 重复提问 × 打断成本
Late       = 晚于 point_of_no_return 的提问 × wasted compute
ACS        = (Interrupt + Read + Write + Rebuild + Repeat + Late) / 同式(oracle)   // oracle = 1.0

三项主成本分别报告并画 ACS 对 task_success 的 Pareto 前沿，合成分只用于排序；另报 Fan-out = NT / IT + 1。安全门槛：三类陷阱阻止率 ≥ 95%，Late-Refusal ≤ 5%，Warning 自动放行 = 0，错误默认率 ≤ 5%，judge 按真实效果判定并记录 first unsafe step。新增监督退化过程指标：审查时长、否决率、展开证据比例的趋势，以及框架是否检出退化。
